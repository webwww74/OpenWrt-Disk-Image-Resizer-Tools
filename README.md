# OpenWrt 磁盘镜像容量调整工具 v2.3

一个**完全离线**的单文件 HTML 工具：在浏览器本地把 OpenWrt 整盘镜像调整到指定容量（可扩容、可缩小），并可单独生成 ESXi 可直接使用的 VMDK 虚拟磁盘。无需安装、无需联网、文件不上传任何服务器，所有处理都在本机浏览器中完成。

配套文件：`OpenWrt_Disk_Image_Resizer_v2.3.html`（用新版 Chrome 或 Edge 打开即可）

---

## 功能一览

- **整盘镜像容量调整**：支持 GPT 与 MBR 两种分区表；调整时同步更新分区表（GPT 主/备表、保护 MBR；可选把最后一个分区调整到新磁盘末尾）。
- **主按钮只出调整后的镜像**：点“调整大小并生成文件”只生成调整后的 `.img.gz`，不再附带 ESXi 文件。
- **ESXi 两件套独立输出**：点其后的“生成 ESXi 两件套”按钮，单独生成对应目标容量的 VMDK 两件套（描述文件 + `-flat.vmdk` 数据文件），不用先点主按钮。
- **ESXi 原生 VMDK 格式**：描述文件（`createType="vmfs"`，`adapterType` 为 `lsilogic`）+ `-flat.vmdk` 数据文件的两件套形式，可直接上传数据存储挂载。
- **选文件即显示原始信息**：输入文件大小、解压后的原始镜像大小、分区表类型（GPT / MBR），不用等处理才知道。
- **大文件流式处理**：解压后超过 2 GiB 的镜像或目标容量超过 2 GiB 时走流式通道——输入只探头 1 MiB 定大小和分区，不全量载入内存；输出分片写文件，不经过整包内存拷贝。目标超过 2048 MiB 不再弹确认框，直接处理。实测：64 MiB 扩到 4 GiB、3 GiB 输入转 ESXi、8 GiB 收缩到 4 GiB 均可正常完成。
- **重置即释放内存**：点“重置”会主动释放已缓存的解压数据，内存立即归还。

## 使用方法

1. 用 Chrome / Edge 打开 `OpenWrt_Disk_Image_Resizer_v2.3.html`。
2. 点击“镜像文件”，选择整盘镜像（`.img` / `.bin` / `.raw` / `.img.gz`，如官方的 `combined-efi` 镜像）。
   - 处理结果区会立即显示原始镜像大小和分区表类型，确认无误再继续。
3. 填**目标容量**（单位 MiB，默认 1024）。可大于或小于原始镜像大小，最小 16 MiB。缩小会截断超出新容量的数据，须先在系统内缩小文件系统/分区。
4. 保持勾选“调整末分区”（让最后一个分区用满新容量；缩小时会把最后一个分区截断到新磁盘末端）；如只想改变磁盘大小、不动分区，可取消勾选（分区装不下目标时会拒绝处理）。
5. 点击“**调整大小并生成文件**”，等待处理完成，得到调整后的 `.img.gz`（一个文件）。
   - 目标容量与原始镜像大小一致时，主按钮提示无需调整，不生成文件。
   - 大文件（解压后超过 2 GiB，或目标容量超过 2 GiB）处理时，浏览器会弹出保存对话框让你选保存位置；用 `http(s)` 打开本页时也可直接生成下载链接。
6. 需要 ESXi 文件时，再点“**生成 ESXi 两件套**”，单独生成对应目标容量的 `.vmdk` 描述文件 + `-flat.vmdk` 数据文件。目标与原始大小一致时，输出原始大小的一套。

## 输出文件说明

以输入 `openwrt.img.gz`、目标 1024 MiB 为例：

| 来源 | 文件 | 说明 |
|---|---|---|
| 主按钮 | `openwrt-1024MiB-resized.img.gz` | 调整后的镜像（gzip） |
| ESXi 按钮 | `openwrt-1024MiB-resized.vmdk` | 调整版描述文件 |
| ESXi 按钮 | `openwrt-1024MiB-resized-flat.vmdk` | 调整版数据文件 |

## 在 ESXi 中使用 VMDK

1. 把同一套的 `.vmdk` 与 `-flat.vmdk` 上传到数据存储的**同一目录**。
2. 给虚拟机添加硬盘时选择该 `.vmdk` 描述文件即可挂载。
3. 注意：`-flat.vmdk` 是完整大小（非稀疏），上传和存储需预留与目标容量相当的空间。

## 支持的输入与兼容性

- **整盘镜像**：OpenWrt `combined` / `combined-efi` 等整盘镜像；单独的 sysupgrade、factory、rootfs 包不是整盘镜像，不能按磁盘容量扩容。
- **gzip 的各种封装都能读**：
  - 官方镜像 `.img.gz` 尾部附带的签名注释（如 signify 签名）会自动忽略，并给出提示；
  - 多段拼接的 gzip（多个 gzip 成员串联）会完整解压；
  - 浏览器原生解压不可用或结果不完整时，自动切换到内置纯 JS 解压器逐段解压并校验。
- **完整性校验**：解压结果会核对 GPT 表头声明的磁盘大小与分区范围；镜像残缺（声明大小超过实际、分区越界、条目 CRC 不符）会直接报错拦截，不会拿残缺镜像生成成品。

## 限制与注意事项

- 容量单位只有 MiB；缩小会截断超出新容量的数据，缩小前请先在系统内缩小文件系统和分区（工具只改分区表，不缩文件系统）。
- 本工具更新的是**分区表层面**的容量，不调整 SquashFS 等文件系统本身，也不保证 overlay 可写空间同步增长——请先在测试设备/虚拟机验证后再用于正式环境。
- MBR 镜像若使用扩展分区/逻辑分区布局，调整结果请谨慎验证。
- 处理大镜像时建议使用 64 位浏览器，并关闭不必要的标签页。
- 显示问题（仅显示，不影响文件本身）：`.img.gz` 尾部的 ISIZE 字段只有 32 位，解压后大小正好是 4096 MiB 整数倍时（如 4096 MiB、8192 MiB）会回绕成 0，页面上可能显示 0；生成的文件本身是完整的，解压后大小与分区表都正确，可正常使用。

## 隐私与安全

- 纯离线单文件：无任何网络请求，不加载外部资源，镜像文件不会离开本机。
- 只读原文件：所有输出都是浏览器新生成的文件，不会修改你选择的原始镜像。

## 常见问题

**Q：选文件后显示的“原始镜像大小”和压缩包大小对不上？**
正常。`.gz` 的“输入文件大小”是压缩包本身，“原始镜像大小”是解压后的真实磁盘大小。

**Q：4096 / 8192 MiB 的镜像显示 0，是文件坏了吗？**
不是，只是显示问题（见上节“限制与注意事项”）：`.gz` 尾部 ISIZE 字段 32 位回绕。文件本身完整可用，解压后大小正确。

**Q：提示“读取原始信息失败：浏览器内存不足”？**
关闭其他标签页后重新选择；或直接点“调整大小并生成文件”尝试处理。仍失败多为镜像解压后过大、超出浏览器单页可承受范围。

**Q：报错“GPT 声明的磁盘大小超过镜像实际大小”？**
说明这个 `.gz` 解压不完整或文件已损坏（例如下载不完整）。请重新获取完整的镜像文件。

**Q：处理 1 GiB 以上的镜像很慢？**
大镜像在走内置解压器回退路径时会明显变慢（纯 JS 解压），属正常现象；原生解压路径下 1 GiB 级别通常在数十秒内完成。
